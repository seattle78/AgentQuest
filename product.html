Conductor Kit · 1.1.0 · Claude Code plugin

One window to talk to. Many sessions doing the work.

You talk to a conductor. It hands each change to its own work session in an isolated git worktree, keeps a board of what is running and what waits on you, and lets one release manager ship only the exact commit you approved.

The problem it solves

Parallel chats collide

Two sessions edit the same file, or one switches the branch under the other. Here every task gets its own worktree, and overlapping files queue instead of racing.

"Done" without proof

A chat says tests pass. Here gates are recorded only with agent-run evidence, and the release manager re-runs the checks itself.

Ship what nobody approved

Here the push takes one literal SHA that must match the verified integration commit, never forced, never a branch name.

Lost context

Long sessions compact and forget. A context hook writes a handoff before that happens, and the next session resumes from it.

How a change flows

Conductor window
You ask→classify→quick work here, or start a work session
Work session (own worktree)
analyze→plan review→failing tests→implement→review + test round (≤ 2)→commit & integrate
Release manager (integration lane)
one version bump→checks pinned to one SHA→You approve that SHA→non-force push→finalize

Safety rules, on by default

  • Only the approved SHA ships, non-force. If anything moves after you approve, you are asked again.
  • Fail closed before the push: an optional pipeline-wait command must say "idle"; "cannot tell" blocks.
  • Relayed approvals are refused for writes. You approve a database write or external call in the window that runs it.
  • Every database write needs your approval, through a guard you can extend with your own patterns.
  • No typing on your behalf. In tmux, messages to a session go through a file inbox; only a fixed "read your inbox" line is typed, and only while that session is idle at its prompt.
  • Two review rounds at most. A serious finding left after round 2 comes to you instead of looping.

Install

  1. Unzip conductor-kit-1.1.0.zip, for example to ~/tools/conductor-kit.
  2. Add the marketplace and install: 
    claude plugin marketplace add ~/tools/conductor-kit
claude plugin install conductor-kit@conductor-kit
claude plugin install conductor-board@conductor-kit   # optional board pane
  3. In your repository, start Claude Code and run /conductor-kit:setup, then /conductor-kit:conductor. For terminal mode, start tmux first, then claude inside it.

Needs Claude Code with plugin support, Node.js 18+ and git. Multiple sessions run in the Claude desktop app's Code tab, or in a terminal with tmux 3.x, where each work session opens as a tmux window (Ctrl-b w to switch). With neither, the conductor writes a brief for you to paste into a new terminal. Full details: README.md.

Configure in one file

.conductor/config.json, every field with a default:

{
  "deploy_branch": "main",
  "integration_branch": "integration",
  "test_command": "npm test",
  "build_command": "",
  "pipeline_wait_command": "",
  "board_language": "en",
  "user_name": "you"
}
